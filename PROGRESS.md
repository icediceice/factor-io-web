## Current Focus

The AI inference TCO calculator is at **SPEC v0.8**: an eight-question guided interview beside the deterministic calculator, powered by MiniMax-M3 through **Factor IO's own proxy** — the page has no key field, no endpoint field and sends no `Authorization` header. UI copy says "LLM assistance" and never names the vendor; `privacy.html` and `llms.txt` still name it, because naming the downstream processor is a disclosure obligation rather than branding. Visitors answer workload, scale, usage intensity, placement, data boundary, workflow, fallback and horizon; three of those questions drive the real `f-users`, `f-sessions-day` and `f-horizon` controls. An **ask box sits on the interview step itself**: an assist turn is a real conversation — free prose in the model's own voice, follow-ups that stay bound to the one question on screen, and an optional structured suggestion that badges an option but can never select one. Prose is sanitized (HTML rejected, and a price or arithmetic claim in the model's own voice rejected) so only the deterministic ledger ever states a number. **Apply guided answers** revalidates every derived field against the live control contract before writing, and **a single answer can be revised after Apply** — change one chip and an inert preview names each control it would rewrite, from what to what, with Re-apply routed back through that same validated path and an Undo that restores the applied answers. The input rail is grouped by decision rather than by field. The pricing snapshot republishes itself on a light-worker systemd timer, so the staleness banner reflects real feed age instead of a hand-run script. The free-form transcript, inert old/new/reason proposals and the post-Apply local-LLM specification turn all remain, demoted under a disclosure. The default comparison horizon is **60 months**. Source and engine arithmetic remain exact USD while authored money, every calculator money surface and export presentation are THB through a dated exact rational FX boundary. Startup uses complete-only atomic OpenRouter pricing and Frankfurter ECB-mirror FX refreshes, preserving dated digest-pinned per-source fallbacks on partial, stale or failed responses. Bounded complete exchange history stays in current-tab memory; every POST still has a copyable request fallback for a visitor-owned same-origin gateway, Ollama or LM Studio. The calculator still derives demand from user count and workload mix, binds sizing on the peak second, derives throughput from the selected model and hardware, and preserves exact provenance for every component. Remaining work is operational: authenticating the AI proxy, evidence ingestion, feed TTL calibration, resolving the rented-vs-self-hosted billing asymmetry, and ongoing source refreshes.
