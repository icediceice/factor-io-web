#### 04:15 — TCO calculator v0.2: pure calculator, session demand model, payback in months, per-provider GPU pricing
- **What:** Rewrote the calculator against a new **SPEC v0.2** (`docs/tco-calculator/SPEC.md` supersedes v0.1's three-lane model). Five changes, each answering a specific complaint about v0.1. **(1) Demand is derived, not asserted.** `tco-calculator/demand.js` (new) takes `users × sessions/user/day × turns/session × per-workload token shape` to monthly in/out/cached tokens, so nobody is asked to guess a monthly token count. Every derived number carries a slot `{rat, basis, text, places}` with `basis ∈ derived|user_override|assumed|input` — a user override is visibly a different kind of number from a derived one. **(2) Workload is a mix, not a label:** chat / RAG / Graph RAG / agentic shares summed with `Rat`, so "sums to 1" is an exact rational test, not a float comparison (`0.7+0.2+0.1 === 1` is FALSE in IEEE-754 and the suite now pins that). `validateMix` refuses rather than normalizes. **(3) Sizing binds on the peak second:** `peakTokensPerSecond` = `concurrent_peak × tokens_s_per_stream`, and `gpusForLoad` ceils that against a per-GPU throughput assumption — a monthly average would size a fleet that feels slow under load. `gpusForLoad` **throws `unknown_gpu`** rather than falling back to a default card. **(4) Breakeven is a whole number of months:** `calculator.js:paybackMonths` returns `ceil(capex / (target_monthly − monthly_opex))` computed as a ceiling on the exact rational, or `converges:false` with a machine-readable reason (`negative_capex` / `zero_capex` / `opex_exceeds_target`) — no prose, no "somewhere around a year". `tcoCurve` gained an optional third argument `laneOneTime` defaulting to `{}` so every existing 2-arg call is byte-identical, and `runComparison` now emits a `payback` block with its signature unchanged (capex rides on `laneA.capex`). **(5) "Lane" is gone from every rendered surface.** The engine keeps its internal A/B/C keys — renaming them would have churned the fixtures — and the rename happens **only at the render/export boundary** via one `OPTION` table in `app.js` mapping A→Self-hosted, B→Model API, C→Rented GPU; `exportQuote` maps through the same table. **Pricing:** `scripts/build-gpu-pricing.mjs` (new) builds a per-provider GPU registry — AWS Price List Bulk and Azure Retail Prices are public, credential-free vendor price lists and ship as `confidence:first_party`; Two aggregator lanes run because their blind spots are complementary — provider pages reach Alibaba but miss GCP, per-GPU pages reach GCP but carry no Chinese cloud (US export controls) — deduped on `${provider}:${gpu_id}`. Shape assertions fail the build loudly rather than emitting a plausible-looking row. `scripts/refresh-pricing.mjs` is the single command the user asked for: GPU pricing then snapshot, with a per-provider coverage summary printed at the end.
