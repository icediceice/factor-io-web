CHAPTER 01 / THE ADOPTION WALL

Why mid-to-large scale AI adoption hits a wall after the pilot

Giving every engineer an AI coding assistant increases individual output, but without a control plane between the agent and your repositories, the bottleneck shifts directly onto senior reviewers, release engineers, and production stability.

[UNGOVERNED STATE]

Ungoverned Agent Sprawl

Observed industry bottlenecks when agents mutate repositories and infrastructure directly

  • +441% PR Review Wait

    Faros AI (2026) telemetry across >10,000 developers shows median PR review time jumped 441%, PRs grew 51.3% larger, 31% more PRs merged without review, and production incidents per PR increased 242.7% (X-3).

  • 89% -> 68% Reviewed Share

    A 2026 multi-year study found the share of pull requests receiving human review dropped from 89% in 2023 to 68% in 2025 as agent output outpaced senior reviewer capacity (X-4).

  • >40% Canceled by 2027

    Gartner (June 2025) forecasts over 40% of agentic AI projects will be canceled by end of 2027 due to escalating costs, unclear business value, or inadequate risk controls (A-1).

  • 19% Slower in Controlled RCT

    METR (2025) randomized controlled trial found experienced developers took 19% longer to complete tasks with AI tools while perceiving a 20% speedup from unverified rework loops (X-10).

[GOVERNED CONTROL PLANE]

Light Declarative Governance

Every tool call, file mutation, peer check, and deployment runs inside an approved manifest

  • Scoped Plan Manifest First

    No write tool executes until the agent declares its exact file targets, shell requests, and verification steps in a structured manifest and receives human or policy approval (L-03, L-04).

  • Cross-Model Peer Falsification

    Before approval and before closure, Light dispatches the plan and diff to an independent model slot configured to falsify assumptions and check unimplemented promises (L-05, L-06).

  • Separate Ability vs. Scope

    Addresses Gartner's May 2026 warning that uniform governance fails to separate an agent's ability to act from its scope of access (A-3): Light binds permissions to the active plan step.

  • Cryptographic Receipt Chain

    Every test and build produces an authenticated receipt recording exit status and source tree byte equality at start and finish, stored in a SHA-256 hash-chained ledger (L-07, L-17).

CHAPTER 02 / DECLARATIVE CONTROL PLANE

One control plane across six harness families and two synchronized lifecycles

Instead of maintaining brittle per-tool wrappers or relying on developer memory, Light interposes a deterministic state machine on the MCP tool channel and binds every mutation to a live plan lifecycle.

Track A: Internal Session State Machine (L-02, 4 States)

Enforced per agent session by the Light MCP gate before any tool call is admitted

01 / boot_locked

Boot Locked

All repository reads and writes are refused until light_bootstrap declares workspace root and task tier.

02 / booted

Booted & Recalled

Read-only code intelligence and persistent KB constraints load automatically before planning.

03 / grounded

Grounded & Planned

Manifest declares exact target files, commands, and creates; peer review runs; mutations stay blocked until Go.

04 / executing

Executing (Manifest-Bound)

Only declared files and commands are admitted with step tracking; out-of-scope edits trigger immediate refusal.

Track B: Visible Work & Approval Lifecycle (L-10, 5 Stages)

Operator-visible governance record from initial proposal through cryptographic verification

STAGE 1 / proposed

Proposed

Agent submits manifest (targets, requests, creates) and design rationale for peer falsification.

STAGE 2 / approved

Approved (Go)

Operator or policy grants authority for the exact manifest; scope changes require re-approval.

STAGE 3 / executing

Executing

Step-indexed mutations, checkpoint commits, and sequenced release convoy participation.

STAGE 4 / verified

Verified

Authenticated test/build receipts (source_matches=true) plus independent verify-ship peer reconciliation.

STAGE 5 / closed

Closed

Scoped paths committed and pushed, durable KB lessons recorded, and hash-chained audit trail sealed.

Six-Layer Governance & Execution Stack (L-01 to L-22)

LAYER 01

Boot Lock & Institutional Memory Recall (L-01, L-02, L-15, L-16)

Every session boots into a locked gate, declares its complexity tier (patch, task, deep), and automatically retrieves project constraints, killed approaches, and past failure patterns.

LAYER 02

Manifest-Bound Planning & Diff/Patch Budgets (L-03, L-04, L-11, L-12, L-20)

Plans specify exact file targets and shell commands up front. The gate enforces per-plan write budgets, repeat-call circuit breakers, and automatic plan revocation if scope expands.

LAYER 03

Single-Binary Tree-Sitter Code Intelligence (L-13, L-14, E-6)

Replaces recursive grep and whole-file dumps with symbol-level locators, call-graph impact analysis, and 97.5% smaller tool-return payloads.

LAYER 04

Cross-Model Peer Review & Verify-Ship Gate (L-05, L-06)

Routes design drafts and post-implementation diffs to a separate model family to surface counterexamples, missing edge cases, and unfulfilled plan promises.

LAYER 05

Authenticated Receipts, RBAC & Hash-Chained Audit (L-07, L-17, L-18, L-22)

Records tamper-evident SHA-256 hash-chained logs, source-tree byte equality receipts across test runs, role-based access control, and hardware-key / WebAuthn approval support.

LAYER 06

Release Conductor, Health Gate & Epic Orchestration (L-08, L-09, L-19, L-21)

Serializes multi-agent deploys through a single release convoy with post-deploy health probes, automatic rollback triggers, and dependency-ordered epic execution.

CHAPTER 03 / VELOCITY ENGINE

Governance that speeds developers up instead of slowing them down

Traditional security gates add ticket queues after code is written. Light embeds code intelligence, peer verification, and release coordination inside the agent loop so engineers ship cleaner code on the first pass.

CONTEXT COMPRESSION (L-13, L-14, E-6)

97.5% Reduction in Tool-Return Token Volume

~1,182 vs ~47,000 tokens/turn

Across 3,766 recorded turns in Light's reference deployment, tree-sitter symbol indexing and bounded slices returned ~1,182 tokens per turn compared with ~47,000 tokens for raw file reads (97.5% reduction). Qualifier (E-6): this measures what tools return to the model, not model reasoning/output tokens. On metered APIs it reduces input token spend; on flat-rate seats it prevents mid-task quota exhaustion and context-window rot.

INDEPENDENT PEER FALSIFICATION (L-05, L-06)

Automated Cross-Model Design & Ship Review

2-Stage Independent Audit

Before an operator approves a medium or large plan, an independent peer model attempts to falsify the design with concrete counterexamples and a rival architecture. Before the plan closes, a verify-ship peer inspects the actual git diff against every promise in the manifest.

RELEASE CONDUCTOR & CONVOY (L-08, L-19)

Zero Collision Deploys Across Concurrent Agents

1,400+ Sequenced Release Runs

When multiple agents finish work simultaneously, Light's release conductor queues and batches deployments through registry-defined service manifests, runs post-deploy health gates, and blocks raw ssh, scp, systemctl, or pm2 improvisation.

INSTITUTIONAL MEMORY (L-15, L-16)

Killed Approaches Never Repeat Twice

Auto-Injected on Smart Index

Every closed plan records architectural constraints, root-cause diagnoses, and killed approaches into the project knowledge base. Subsequent sessions receive matching constraints automatically when navigating those files.
