4 NON-BYPASSABLE KERNEL INVARIANTS

Why the Model Cannot Break Out of Light Governance

  • LAW 01
    Physical Read-Only Confinement During Threat Hunting
    In Explore & Diagnose phases, the gate admits only read-only probes (`light_ops`, `light_analyze`, `light_cve`). Write tools and mutating shell commands are rejected at the dispatcher before reaching any host.
  • LAW 02
    Byte-Exact Plan Manifest (`targets[]` + `requests[]`)
    Before a single file edit or service action can occur, the agent must author a structured Plan Manifest declaring every exact file path, host, and command string—and stop (`ack_stop`) for human Operator Go.
  • LAW 03
    Automatic Revoke-on-Edit Circuit Breaker
    If the model (or anyone) modifies a single step, target, or command in the plan after approval, the server immediately increments `manifest_revision` and revokes the approval token.
  • LAW 04
    Hard Content Ban on Destructive Primitives
    Raw `systemctl`, `pm2`, `kubectl`, `pkill`, and destructive Git/disk commands are blocked in `light_bash` and routed through typed control-plane tools (`light_admin`, `light_nkp`) with explicit operator holds.
